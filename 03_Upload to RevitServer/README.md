# RvsUpload

Загрузка моделей **на** Revit Server из командной строки. Дополняет `RevitServerTool.exe`, который умеет только скачивать (`createLocalRVT`).

## Почему это не может быть чистой standalone-утилитой

Три уровня доступа к Revit Server:

| Уровень | Что это | Умеет заливать? |
|---|---|---|
| Admin REST API | `http://<host>/RevitServerAdminRESTService<год>/AdminRESTService.svc/` | **Нет.** Только метаданные: contents, DirectoryInfo, modelInfo, history, lock, создание/удаление/переименование папок |
| Внутренние proxy-сборки | `RS.Enterprise.Common.ClientServer.Proxy.dll` — путь, которым идёт AltecSystems.Revit.ServerExport | **Нет.** Скачивание — да (это выкачивание готовых стримов), заливка — нет |
| Revit API | `Document.SaveAs()` + `WorksharingSaveAsOptions.SaveAsCentral` | **Да**, единственный способ |

Причина фундаментальная: центральная модель на сервере хранится не как файл `.rvt`, а как набор потоков и элементных данных, которые формирует worksharing-движок Revit. Воспроизвести этот формат снаружи нереально.

Поэтому RvsUpload = CLI-обёртка + сессия Revit:

```
RvsUpload.exe
  ├─ проверки: версия модели, лимиты сервера, папки, дубликаты, блокировки
  ├─ batch.json + переменная окружения RVSUPLOAD_BATCH
  ├─ Revit.exe   (БЕЗ аргументов, как обычная сессия)
  │     └─ аддин из %ProgramData%: по событию ApplicationInitialized
  │           OpenDocumentFile(detach) → EnableWorksharing? → SaveAs(RSN://…, SaveAsCentral)
  │                                    → RelinquishOwnership → PostCommand(ExitRevit)
  └─ чтение result.json, повторы при неудаче, exit code
```

**Journal-файл не используется.** Схема RevitBatchProcessor в этой части не воспроизводится: Revit, запущенный с journal-файлом, грузит только «внутренние» подписанные аддины из своей папки установки и не подхватывает аддины из `%ProgramData%` (31 внешнее приложение против 82). Проверено сравнением количества загруженных внешних приложений с journal и без него.

Отличие от RBP: нет IronPython, Dynamo, GUI и слоя настроек. Одна задача — одна утилита.

## Состояние

**Работает.** Проверено на живом Revit Server 2021: заливка центральных моделей, моделей без рабочих наборов (через `EnableWorksharing`), моделей младших версий (с автообновлением), пакетный режим, перезапись, повторы при сбоях.

История доведения — в [CHANGELOG.md](CHANGELOG.md).

## Структура

```
src/RvsUpload.Core/     netstandard2.0 — чистая логика, тестируется без Revit
src/RvsUpload/          net48 exe — CLI
src/RvsUpload.Addin/    аддин Revit (net48 для ≤2024, net8.0-windows для 2025+)
tests/RvsUpload.Tests/  net8.0 — юнит-тесты Core

Settings.html           автономная страница-редактор settings.json
settings.template.json  образец файла настроек
```

Внешних зависимостей нет: JSON берётся из BCL (`DataContractJsonSerializer`). Рядом с `RvsUpload.exe` лежит только `RvsUpload.Core.dll`, аддин — единственный файл `RvsUpload.Addin.dll`.

## Сборка и установка

```powershell
.\build.ps1                          # Core + CLI + тесты, аддин под найденные версии Revit
.\build.ps1 -RevitVersions 2021,2025
.\install-addin.ps1 -RevitVersion 2021
```

Аддин ставится в `%ProgramData%\Autodesk\Revit\Addins\<год>\`. **Класть его в папку установки Revit нельзя** — оттуда Revit требует подписи Autodesk и пишет в журнал `is not signed as internal addin`.

## Передача коллегам

```powershell
.\build.ps1 -Package
```

Собирает `dist\RvsUpload-<версия>` и архив к нему — это и есть то, что
отдают. Внутри утилита, надстройки, установщик, страница настроек,
инструкция в HTML и примеры команд. Ставить получателю больше нечего:
ни .NET, ни dotnet SDK не нужны.

У коллеги три шага: распаковать, запустить `Установить.ps1`, один раз
подтвердить надстройку в Revit. Третий шаг обязателен и автоматизации
не поддаётся — до ответа Revit не грузит **ни одной** сторонней надстройки.

Надстройки в поставке разложены **по средам выполнения**, а не по годам:
`net48` для Revit 2021–2024 и `net8` для 2025 и новее. Сборка под все
net48-версии одна и та же — `RevitAPI.dll` не подписана строгим именем,
поэтому версия ссылки при загрузке не проверяется. Пять папок с байт
в байт одинаковыми файлами только вводили бы в заблуждение.

Инструкция собирается из [Инструкция.md](Инструкция.md) скриптом
`tools\md2html.ps1` — правится markdown, коллега получает страницу.
Папка `dist` в git не хранится: она полностью воспроизводима из исходников.

## Использование

```powershell
# одна модель
RvsUpload.exe --source C:\out\Model.rvt `
              --dest RSN://RVTSRV01/Projects/2026/Model.rvt `
              --revit-version 2021 --create-folders --overwrite

# пакет
RvsUpload.exe --list models.txt --revit-version 2021 --overwrite --retries 2 --log upload.log
```

Формат `--list` — три формы строки:

```
# комментарий
C:\out\ARCH.rvt                                  имя на сервере = имя файла
C:\out\ARCH_v12_ИСПРАВЛЕНО.rvt|АР.rvt            имя задано явно (нужен --dest-folder)
C:\out\MEP.rvt|RSN://RVTSRV01/Projects/2026/MEP.rvt   полный путь назначения
```

### Файл настроек

Держать два десятка ключей в задании Планировщика неудобно, поэтому настройки можно вынести в файл:

```powershell
RvsUpload.exe --config settings.json
```

**Аргументы командной строки перекрывают файл** — настройка живёт в файле для пайплайна, но её можно разово переопределить при запуске. Ключа нет в файле — берётся умолчание утилиты.

Файл редактируется страницей **`Settings.html`**: автономный один файл, открывается двойным щелчком, без интернета и веб-сервера. Образец — `settings.template.json`.

Модели в файл не выносятся: они меняются от запуска к запуску, их место в списке `--list` или в аргументах.

Полный список ключей: `RvsUpload.exe --help`.

Коды возврата: `0` успех, `1` аргументы, `2` Revit не найден, `3` ошибка загрузки, `4` таймаут, `5` ошибка Revit Server.

## Что нужно знать перед внедрением в пайплайн

Всё ниже — не предположения, а то, что вылезло при доведении утилиты на реальном сервере и боевых моделях.

**Диалог доверия после каждой пересборки аддина.** Revit показывает окно «Невозможно проверить разработчика этой надстройки» и **останавливает загрузку всех аддинов**, пока не получит ответ; кнопка по умолчанию — «Не загружать». Доверие привязано к конкретной сборке, а не к `AddInId`, поэтому вопрос повторяется после каждой пересборки. Ответить надо один раз, в интерактивной сессии Revit, кнопкой «Всегда загружать». **В эксплуатации, где аддин не пересобирают, вмешательство не требуется** — но после обновления утилиты первый запуск надо сделать руками.

**Лицензия.** Сессия Revit занимает лицензию на всё время работы. На агенте нужна доступная лицензия и вошедший в Autodesk-аккаунт пользователь. Это, а не код, обычно и есть главное ограничение.

Занятость проверяется до запуска, но **только при сетевом лицензировании** (`lmutil lmstat`, адрес из `ADSKFLEX_LICENSE_FILE` или `LicPath.lic`) — тогда запуск отменяется сразу с кодом 2. При single-user узнать занятость нечем, и утилита честно пишет об этом в лог. Настоящая защита в обоих случаях — **`--startup-timeout <мин>`** (по умолчанию 5): если Revit не дошёл до аддина, значит он ждёт ответа в модальном окне до загрузки надстроек (лицензия, восстановление после падения, диалог доверия), и ждать общий таймаут бессмысленно. Такое застревание отменяет повторы — причина не в модели.

**Не бывает по-настоящему headless.** Revit поднимает UI-процесс, окно видно на экране всё время работы, и скрыть его штатными средствами нельзя. Нужна интерактивная сессия Windows — под сервисом без десктопа Revit не стартует. На агенте используйте autologon + Планировщик заданий в интерактивном режиме, а лучше отдельную машину, на экран которой никто не смотрит.

**Версии.** Модель новее Revit отклоняется **до** запуска Revit, за доли секунды. Модель младшей версии заливается: Revit обновляет её сам, это дольше (на тестовой модели 61 с против 3–5 с) и помечается в логе. Поведение задаётся ключом `--on-upgrade` (`upgrade` по умолчанию, `skip`, `abort`). Вопросов утилита не задаёт никогда — работает одинаково из рук и из Планировщика.

**Обновление старых моделей нестабильно.** На повреждённой модели Revit падал внутри себя (`captureTryCrash 0xc0000005` в его журнале) примерно в одном запуске из трёх, причём повтор того же файла проходил успешно. `--audit` на вероятность не влияет — проверено замерами. Средство — **`--retries <n>`**: перезапуск Revit с остатком незалитых моделей. Для пайплайна с моделями смешанных версий ставьте `--retries 2`.

**Лимиты сервера.** Утилита читает их с самого сервера (`GET /serverProperties`) и проверяет до запуска Revit. На Revit Server 2021 это `MaximumFolderPathLength: 98` и **`MaximumModelNameLength: 40`** — про второй Revit пользователю не сообщает, а именно он чаще всего и подводит. Слишком длинное имя отбраковывается с указанием обеих цифр; задать другое имя можно ключом `--dest-name` или второй колонкой списка. **Имя модели утилита не меняет никогда** — ни суффиксов, ни переименований: это решение остаётся за вами.

**Зависания.** Два сторожа с разными задачами. `--startup-timeout` (5 мин) ловит ситуацию, когда Revit не дошёл до аддина — модальное окно до загрузки надстроек. `--idle-timeout` (20 мин) ловит зависание на середине пакета по молчанию лога аддина и пишет в отчёт шаг, на котором всё встало. Порог простоя намеренно большой: во время `SaveAs` лог молчит, и на большой модели это законные минуты — меньший порог начнёт убивать здоровые сессии.

**Обрыв заливки не портит модель на сервере.** Проверено убийством Revit посреди `SaveAs`: существующая центральная модель осталась в прежнем состоянии. Revit Server не подменяет её, пока заливка не завершена.

**Кириллица в именах папок.** Revit Server 2021 отвечает `500` на создание папки с русским именем, хотя папку при этом создаёт. Утилита проверяет факт наличия, а не код ответа, — иначе `--create-folders` не работал бы для обычных русских путей.

**Отбраковка позадачная.** Непригодная модель не утаскивает за собой весь пакет: она помечается проваленной, остальные заливаются, а итоговый `result.json` описывает весь запуск. Глобальным отказом остаётся только недоступность сервера.

**Блокировки заранее не проверяются.** `GET /<model>/lock` на Revit Server 2021 отвечает **405 Method Not Allowed** — GET на этом ресурсе не разрешён, GET-альтернативы нет. Утилита честно пишет в лог, что состояние блокировки узнать невозможно; если модель занята, отказ придёт на `SaveAs`. Зависший `inProgressLock` снимается через `RevitServerRestClient.CancelInProgressLock` или админку Revit Server.

**Диалоги.** `DialogSuppressor` отвечает по явному списку `DialogId` — универсальный «Cancel» оказался угадыванием: у окна может не быть такой кнопки, и Revit тогда поступает по-своему. Неизвестный диалог получает `Cancel`, но помечается в логе как **отвеченный вслепую** — такие идентификаторы надо разбирать и добавлять в список. Окно «Остановить выполнение данной операции?» намеренно **не перехватывается**: оно возникает только от нажатия человеком, и его решение уважается — модель помечается отменённой, пакет идёт дальше.

**Связанные модели.** `--close-worksets` закрывает пользовательские рабочие наборы при открытии, чтобы **не подгружались связи**, размещённые в них. Это не то же, что `--unload-links`: тот выгружает связи уже после открытия. На содержимое результата не влияет — закрытый набор остаётся в файле целиком (проверено: расхождение 0,14 %). Учтите, что «Общие уровни и сетки» — тоже пользовательский набор и закрывается наравне с прочими.

**Права на сервере.** Учётка, под которой идёт заливка, должна иметь права на целевую папку. REST API пишет `User-Name`/`User-Machine-Name` в журнал сервера — там же и смотрите отказы.

**Первая заливка большой модели идёт долго** — Revit Server пишет модель поэлементно. Ставьте `--timeout` с запасом; дефолт 60 минут.
