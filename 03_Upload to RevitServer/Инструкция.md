# RvsUpload — заливка моделей на Revit Server

Утилита командной строки, которая кладёт модели **на** Revit Server.
Штатный `RevitServerTool.exe` умеет только скачивать; обратной дороги
у Autodesk нет, поэтому она и написана.

Работает так: запускает Revit без открытых окон-вопросов, открывает вашу
модель с отсоединением, сохраняет её на сервер как центральную и закрывает
Revit. Всё остальное в этой инструкции — подробности этих четырёх шагов.

---

## Что нужно до начала

- **Windows и установленный Revit** той версии, в которой будете заливать.
  Поддерживаются 2021–2026.
- **Доступ к Revit Server** — тот же, что у вас в Revit.
- **Свободная лицензия Revit.** Утилита занимает её на время работы, как
  обычный сеанс. Если Revit уже открыт другой копией — заливка не начнётся.
- **Права на запись** в папку назначения на сервере.

Ставить .NET, Python или что-то ещё не надо: всё лежит в папке с утилитой.

---

## Установка: три шага

### 1. Скопируйте папку

Положите папку `RvsUpload` куда удобно — например `C:\BIM\RvsUpload`.
Внутри всё нужное. В сетевой папке она тоже работает, но с локального
диска запускается заметно быстрее.

### 2. Запустите `Установить.cmd`

Двойной щелчок по файлу. Окно останется открытым, пока вы его не
закроете, — так видно и результат, и текст ошибки, если что-то пошло
не так.

Скрипт находит все установленные Revit и кладёт надстройку в каждый.
Ничего в системе он больше не трогает: ни реестра, ни служб, ни
переменных среды.

> Рядом лежит `Установить.ps1` — тот же установщик для тех, кто работает
> в консоли или в файловом менеджере. Правой кнопкой по нему →
> **Выполнить с помощью PowerShell** тоже годится: окно в этом случае
> дождётся нажатия Enter и не закроется само.

Из открытой консоли — имя файла **в кавычках**, в нём кириллица
и может встретиться пробел:

```
powershell -ExecutionPolicy Bypass -File "Установить.ps1"
```

Ключ `-БезПаузы` отключает ожидание Enter — он нужен, если установка
вызывается из другого скрипта.

### 3. Один раз подтвердите надстройку

Запустите Revit **вручную**. Он спросит про загрузку неподписанной
надстройки — ответьте **«Всегда загружать»**.

Это обязательный шаг, и обойти его нельзя. Пока ответа нет, Revit
не загружает **ни одной** сторонней надстройки, и утилита будет
завершаться с сообщением «Revit не дошёл до аддина».

> Вопрос повторится, если надстройку обновят: доверие Revit привязывает
> к конкретному файлу, а не к её имени.

Всё. Revit можно закрыть.

## Первый запуск

Проверьте, что установка удалась, — заливать пока ничего не будем:

```
RvsUpload.exe --source "C:\Модели\Пример.rvt" ^
              --dest "RSN://СЕРВЕР/Папка/Пример.rvt" ^
              --revit-version 2024 ^
              --dry-run
```

`--dry-run` проверяет всё, что можно проверить без Revit: доступен ли
сервер, не длинны ли имена, той ли версии модель. Revit при этом
не запускается.

Ответ `Итого: пригодно 1` означает, что можно заливать по-настоящему —
уберите `--dry-run`.

В папке **Примеры** лежат готовые команды на шесть случаев: проверка без
заливки, одна модель, пакет по списку, папка целиком, возврат моделей
на прежние места, запуск по файлу настроек. Их проще открыть в блокноте
и поправить пути, чем набирать команду руками.

Один и тот же набор идёт в двух видах:

- `.cmd` — запускается двойным щелчком. Пути в них написаны латиницей
  (`C:\Models\Example.rvt`): командная строка читает файл в кодировке
  окна консоли, и кириллица в самой команде зависит от её настроек.
- `.ps1` — для Планировщика заданий и вызова из других скриптов.
  Кодировка окна им безразлична, поэтому пути можно писать по-русски.

Запуск `.ps1` из командной строки — **имя файла в кавычках**, в именах
примеров есть пробелы:

```
powershell -ExecutionPolicy Bypass -File "1 Проверка без заливки.ps1"
```

Без кавычек PowerShell обрежет имя на первом пробеле и ответит, что файл
имеет расширение, отличное от PS1. Двойным щелчком проще: правой кнопкой
по файлу → «Выполнить с помощью PowerShell».

> Если в окне вместо русских комментариев в `.cmd` видны кракозябры,
> у консоли нестандартная кодовая страница. На работу команды это не
> влияет, но надёжнее взять `.ps1` с тем же именем.

## Как заливать

### Одну модель

```
RvsUpload.exe --source "C:\Модели\АР.rvt" ^
              --dest "RSN://СЕРВЕР/Проекты/2026/АР.rvt" ^
              --revit-version 2024 ^
              --overwrite
```

Без `--overwrite` заливка поверх существующей модели отклоняется —
намеренно, чтобы случайный повтор не затёр чужую работу.

### Папку целиком

Если моделей много и они лежат в папке, список поддерживать не нужно —
укажите папку:

```
RvsUpload.exe --source-folder "C:\Выгрузка" ^
              --dest-folder "RSN://СЕРВЕР/Проекты/2026" ^
              --revit-version 2024 ^
              --overwrite --create-folders --retries 2
```

Вложенные папки просматриваются; чтобы взять только верхний уровень,
добавьте `--no-recurse`.

**Что в пакет не попадёт.** Резервные копии Revit (`Модель.0001.rvt`)
и служебные папки (`*_backup`, `Revit_temp`) пропускаются. Каждый пропуск
виден в логе отдельной строкой — модель, тихо не попавшая в пакет,
выглядит как потерянная.

#### Куда лягут модели: `--structure`

| Режим | Что делает |
|-------|------------|
| `flat` | всё в одну папку `--dest-folder`. По умолчанию |
| `disk` | повторяет структуру подпапок с диска. Нужен `--create-folders` |
| `server` | кладёт каждую модель туда, где она **уже лежит** на сервере |

`disk` — когда на диске уже разложено так, как надо на сервере:

```
C:\Выгрузка\АР\Модель_АР.rvt      ->  RSN://СЕРВЕР/Проекты/2026/АР/Модель_АР.rvt
C:\Выгрузка\КР\Узлы\Модель_КР.rvt ->  RSN://СЕРВЕР/Проекты/2026/КР/Узлы/Модель_КР.rvt
```

`server` — обратная дорога. Модели скачали с сервера, обработали, и надо
вернуть их **на прежние места**, а на диске они лежат как попало.
Утилита обходит дерево сервера начиная с `--dest-folder` и ищет модель
по имени.

Две ситуации она решать за вас не станет, и это намеренно — ошибка здесь
означает залить раздел поверх чужого:

- **модели с таким именем на сервере нет** — задание отбраковано;
- **модель нашлась в нескольких папках** — отбраковано, папки перечислены
  в логе.

Остальные модели пакета при этом заливаются: одна непонятная не отменяет
всех. Отбракованные залейте отдельно, указав папку явно.

### Пакет по списку

Список — обычный текстовый файл, одна модель на строку:

```
C:\Выгрузка\АР.rvt
C:\Выгрузка\КР.rvt
C:\Выгрузка\ОВ_корпус_2_стадия_П_ревизия_7.rvt|ОВ.rvt
```

Третья строка показывает, как задать другое имя на сервере: путь,
вертикальная черта, новое имя. Это единственный способ залить модель,
имя которой длиннее 40 символов.

```
RvsUpload.exe --list "C:\Выгрузка\models.txt" ^
              --dest-folder "RSN://СЕРВЕР/Проекты/2026" ^
              --revit-version 2024 ^
              --overwrite --create-folders --retries 2
```

Весь пакет заливается за **один** запуск Revit — это главная причина,
по которой пакет быстрее, чем те же модели по одной.

### Через файл настроек

Когда набор ключей устоялся, соберите его один раз страницей
**Настройки.html** (двойной щелчок, интернет не нужен) и запускайте так:

```
RvsUpload.exe --config "C:\BIM\settings.json"
```

Аргументы командной строки перекрывают файл — удобно, когда всё общее,
а меняется одна папка.

## Что нужно знать заранее

Эти вещи выяснены на живых прогонах, и они экономят вечер.

### Имя модели — не длиннее 40 символов, но предел можно поднять

Про этот лимит Revit пользователю не сообщает, а подводит он чаще всего.
Путь папки — до 98 символов на серверах 2021 и 2026, до 126 на 2022–2025;
точное значение утилита читает с самого сервера.

Есть важная тонкость: **объявленный сервером предел строже фактического**.
Сам Revit сохраняет на тот же сервер модели с именами длиннее объявленного,
и отбраковывать такие модели значит запрещать то, что на деле работает.
Поэтому предел можно задать свой:

```
RvsUpload.exe --source "C:\Модели\АР.rvt" ^
              --dest "RSN://СЕРВЕР/Проекты/2026/АР.rvt" ^
              --revit-version 2024 ^
              --max-model-name 60
```

В настройках это поле «Предел имени модели». Пусто — брать с сервера,
как раньше. `0` — не проверять вовсе. То же для пути папки:
ключ `--max-folder-path`.

Применённый предел и его источник утилита пишет в журнал:

```
Сервер RVTSRV (RVTSRV): максимум 98 символов на путь папки, 40 на имя модели.
Предел длины имени модели: 60 символов (задано настройкой, сервер сообщает 40).
Предел длины пути папки: 98 символов (сообщает сервер).
```

Модель, прошедшая только за счёт поднятого предела, отмечается отдельно —
чтобы при отказе сервера было видно, какие имена шли за пределом:

```
ВНИМАНИЕ: имя 'АР_корпус_2_стадия_П_ревизия_7.rvt' — 45 символов,
сервер объявляет предел 40. Пропущено по настройке.
```

Второй способ, он же прежний: задать модели другое имя — через вертикальную
черту в списке или ключом `--dest-name`.

### Модель старее вашего Revit будет обновлена

Revit обновит её сам при открытии. Это занимает **полторы-две минуты**
вместо трёх секунд, и в логе помечается заранее — иначе выглядит как
зависание.

Модель **новее** вашего Revit отклоняется сразу: открыть её нечем.

### Обновление иногда роняет Revit

Примерно один запуск из трёх на повреждённой модели. Это дефект Revit,
а не утилиты, и настройками не лечится. Лечится повтором — держите
`--retries 2`. Повтор берёт **только незалитый остаток**, заново уже
залитое не переделывает.

На повторе модель открывается **с проверкой структуры** (audit). Это
медленнее, зато чинит мелкие повреждения — как раз то, из-за чего Revit
и падает через раз. На первой попытке проверка не включается: она замедлила
бы открытие всего пакета ради тех единиц, что упадут.

Отключается ключом `--no-audit-on-retry` или галочкой «Не проверять
структуру на повторе» в настройках.

### Окно Revit будет видно

Спрятать его нельзя: Revit — обычное оконное приложение, ему нужен
рабочий стол. **Не нажимайте в нём ничего** — утилита сама всё закроет.
Если работаете за этой же машиной, лучше запускать заливку, когда
отходите.

### Модель без рабочих наборов

Такую Revit Server не принимает. Утилита включает совместную работу
сама и заливает модель **под тем же именем** — никаких суффиксов.

## Итог запуска

В конце работы утилита печатает сводку. Она отвечает на два вопроса: сколько
залилось и что чинить. Незалитые модели сгруппированы по причинам, а причины
идут от той, что задела больше моделей:

```
==================== ИТОГ ====================
Успешно залито: 14
С ошибкой:      5

Не залито, по причинам:

  Слишком длинное имя модели — 3 модели:
    АР_корпус_2_стадия_П_ревизия_7.rvt  ->  RSN://СЕРВЕР/Проекты/2026/АР_...rvt
      Имя модели — 45 символов, а допустимо не длиннее 40 (сообщает сервер): ...
    ...

  Модель заблокирована на сервере — 1 модель:
    ОВ.rvt  ->  RSN://СЕРВЕР/Проекты/2026/ОВ.rvt
      Модель заблокирована (кто-то работает / завис lock).

  Прочее — 1 модель:
    КР.rvt  ->  RSN://СЕРВЕР/Проекты/2026/КР.rvt
      <текст ошибки от Revit>
==============================================
```

Группировка нужна ровно для одного: увидеть, что двадцать моделей уперлись
в одно и то же и чинится это одним действием. Причины, которых утилита
не узнала, попадают в «Прочее» вместе с исходным текстом ошибки — там
у каждой модели своя история.

Та же сводка печатается и в проверочном прогоне `--dry-run`, до запуска Revit.

## Когда что-то пошло не так

Утилита возвращает код, по которому видно, где встали:

| Код | Что случилось | Что делать |
|-----|---------------|------------|
| 0 | Всё залито | — |
| 1 | Ошибка в аргументах | Проверьте команду, посмотрите `--help` |
| 2 | Не найден Revit | Укажите `--revit-exe` с полным путём |
| 3 | Часть моделей отбракована | Смотрите лог: имя длинное, версия новее, файла нет |
| 4 | Revit не дошёл до надстройки | Не подтверждена надстройка, занята лицензия или Revit ждёт ответа в окне |
| 5 | Сервер недоступен | Проверьте адрес, сеть, VPN |

### Частые случаи

**«Revit не дошёл до аддина за 5 мин»** — почти всегда это неподтверждённая
надстройка. Запустите Revit вручную и ответьте «Всегда загружать».
Второй по частоте случай — занята лицензия другой копией Revit.

**«Модель сохранена в Revit 2025, а заливка идёт через Revit 2021»** —
запустите с `--revit-version 2025`, если он установлен.

**«Имя модели — 115 символов, а допустимо не длиннее 40»** — задайте
короткое имя через `--dest-name` или вертикальную черту в списке. Либо
поднимите предел ключом `--max-model-name`: объявленный сервером предел
строже фактического.

**Заливка оборвалась посреди работы.** Модель на сервере не пострадала:
Revit Server не подменяет существующую, пока новая не загружена целиком.
Просто запустите ещё раз.

### Что приложить, если нужна помощь

- файл журнала (ключ `--log`);
- запуск с ключом `--keep-temp` — он оставляет рабочую папку, в ней лежат
  задание, лог надстройки и отчёт по каждой попытке;
- журнал самого Revit из
  `%LOCALAPPDATA%\Autodesk\Revit\Autodesk Revit <год>\Journals`.

## Все ключи

| Ключ | Что делает |
|------|------------|
| `--source <файл>` | Модель для заливки |
| `--dest <RSN-путь>` | Полный путь назначения вместе с именем |
| `--dest-folder <RSN-путь>` | Папка назначения, имя берётся из файла |
| `--dest-name <имя>` | Другое имя на сервере |
| `--list <файл>` | Список моделей, одна на строку |
| `--source-folder <папка>` | Папка с моделями вместо списка |
| `--structure <flat\|disk\|server>` | Куда лягут модели; только с `--source-folder` |
| `--no-recurse` | Не заходить во вложенные папки |
| `--config <файл>` | Файл настроек |
| `--revit-version <год>` | Какой Revit запускать |
| `--revit-exe <путь>` | Полный путь к Revit.exe |
| `--overwrite` | Перезаписывать существующую модель |
| `--create-folders` | Создавать недостающие папки |
| `--dest-name` | Имя модели на сервере |
| `--close-worksets` | Закрывать пользовательские рабочие наборы |
| `--unload-links` | Выгружать связи |
| `--audit` | Проверять структуру при открытии |
| `--compact` | Сжимать при сохранении |
| `--max-backups <N>` | Сколько версий хранить на сервере |
| `--on-upgrade <upgrade\|skip\|fail>` | Что делать с моделями старее Revit |
| `--retries <N>` | Повторов после сбоя |
| `--timeout <мин>` | Общий срок |
| `--startup-timeout <мин>` | Сколько ждать старта Revit |
| `--idle-timeout <мин>` | Через сколько молчания считать зависшим |
| `--log <файл>` | Файл журнала |
| `--keep-temp` | Оставить рабочую папку для разбора |
| `--dry-run` | Проверить и не заливать |
| `--max-model-name <N>` | Свой предел длины имени модели, `0` — не проверять |
| `--max-folder-path <N>` | Свой предел длины пути папки, `0` — не проверять |
| `--no-audit-on-retry` | Не включать проверку структуры на повторной попытке |
| `--skip-preflight` | Не проверять ничего до запуска |
| `--help` | Список ключей |

## Обновление утилиты

Замените папку целиком и снова запустите `Установить.cmd`. Настройки
в `settings.json` не пострадают, если файл лежит **вне** папки утилиты, —
так его и держите.

После обновления Revit **снова спросит** про надстройку: доверие привязано
к файлу, а файл сменился. Подтвердите один раз.
