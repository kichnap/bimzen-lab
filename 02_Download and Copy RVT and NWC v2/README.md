# 02. Download and Copy RVT and NWC (v2)

Внутреннее имя пайплайна: **DownloadAndCopyRVTNWC**.

Ночной/регламентный пайплайн обмена моделями: забирает модели с RevitServer,
конвертирует их в NWC, раскладывает по файловому серверу компании и файловому
серверу заказчика, а также забирает встречные модели смежников.

Актуальная версия: **2.5 (19.08.2026)** — исправлены критичные проблемы
первой версии, добавлено подключение VPN списком туннелей (SoftEther,
встроенный VPN Windows, WireGuard, OpenVPN), переработан редактор настроек,
исправлена кодировка вывода утилит, см. [CHANGELOG](CHANGELOG.md).

Шаг 1 (скачивание с RevitServer) прогнан вживую на пилотном проекте:
12 из 13 моделей скачаны, одна крупная упёрлась в таймаут 1 час. Ещё не
прогонялись: шаг 2 (конвертация в NWC, Navisworks) и фактическое
подключение VPN.

Предыдущая версия (1.3 от 12.07.2025) — то, что сейчас работает в регламенте;
она заморожена как архив в папке
[01_Download and Copy RVT and NWC v1](../01_Download%20and%20Copy%20RVT%20and%20NWC%20v1/).

## Запуск

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "00_Start_RunScript.ps1"
```

Штатно запускается Планировщиком заданий Windows на рабочей станции BIM-отдела.
Логи пишутся в подпапку `Logs` рядом со скриптом. Код возврата: `0` — ошибок нет,
`1` — в логе есть записи уровня ERROR (в version 1 код возврата не выставлялся).

Набор выполняемых шагов задаётся ключом `SelectedScripts` в `config.json` —
шаги можно включать и выключать без правки кода.

## VPN

RevitServer и файловые серверы заказчика доступны только через VPN. Начиная
с version 2.1 пайплайн умеет поднимать соединение сам — это нужно для запуска
из Планировщика, где подключить VPN вручную некому. Начиная с version 2.4
туннелей может быть несколько: каждому задаётся свой клиент, своё имя
подключения и свой выключатель.

```json
"Vpn": {
  "Enabled": true,
  "ConnectTimeoutSeconds": 90,
  "DisconnectAfterRun": true,
  "Connections": [
    {
      "Name": "RevitServer",
      "Enabled": true,
      "Required": true,
      "Type": "SoftEther",
      "AccountName": "Проект-VPN",
      "VpnCmdPath": "C:\\Program Files\\SoftEther VPN Client\\vpncmd.exe",
      "PasswordEnvVar": "",
      "TestHost": "RVTSRV",
      "TestPort": 80
    },
    {
      "Name": "Заказчик",
      "Enabled": false,
      "Type": "Rasdial",
      "RasEntryName": "Заказчик-VPN",
      "TestHost": "PARTNER-NAS",
      "TestPort": 445
    }
  ]
}
```

Общие ключи блока:

| Ключ | Смысл |
|------|-------|
| `Enabled` | Поднимать ли VPN вообще. `false` — пайплайн работает как раньше |
| `ConnectTimeoutSeconds` | Сколько ждать готовности канала. Значение по умолчанию для всех туннелей |
| `ConnectAttempts` | Сколько раз пробовать поднять туннель, по умолчанию 2. Клиент VPN может отчитаться об успехе, а канал не заработать: адрес на виртуальный адаптер приходит позже, и с первого раза не всегда. Перед повтором подключение разрывается |
| `DisconnectAfterRun` | Разрывать ли соединения после работы. Значение по умолчанию для всех туннелей |
| `Connections[]` | Список туннелей |

Ключи туннеля:

| Ключ | Смысл |
|------|-------|
| `Name` | Название туннеля в логе и в ключе `-VpnOnly`. Если пусто, берётся имя подключения в клиенте |
| `Enabled` | Использовать этот туннель или нет |
| `Required` | Обязателен ли туннель. При `false` пайплайн продолжит работу, если канал не поднялся |
| `Type` | Клиент VPN: `SoftEther`, `Rasdial`, `WireGuard`, `OpenVpn` |
| `TestHost`, `TestPort` | Узел, доступностью которого подтверждается подключение. При `TestPort: 0` — проверка ping |
| `ConnectTimeoutSeconds`, `DisconnectAfterRun` | Переопределяют общие значения для этого туннеля |

Ключи, свои у каждого клиента:

| Клиент | Ключи | Права администратора |
|--------|-------|----------------------|
| `SoftEther` | `AccountName` — имя подключения в клиенте (см. список ниже); `VpnCmdPath` — путь к `vpncmd.exe`; `PasswordEnvVar` — имя переменной окружения с паролем управления клиентом, обычно пусто. **Сам пароль в config.json не хранится** | не нужны |
| `Rasdial` | `RasEntryName` — имя подключения в «Сетевых подключениях» | не нужны |
| `WireGuard` | `Tunnel` — имя туннеля в приложении WireGuard; `WireGuardPath` — путь к `wireguard.exe` | **нужны** |
| `OpenVpn` | `Profile` — имя `.ovpn` без расширения; `ProfilePath` — полный путь, если профиль лежит не в стандартной папке; `OpenVpnPath` — путь к `openvpn.exe`; `ManagementPort` — порт интерфейса управления, свой у каждого туннеля | **нужны** |

Логика:

- туннели поднимаются сверху вниз и разрываются в обратном порядке — каналы
  делят маршруты, и поднятый последним может перехватить маршрут по умолчанию;
- каждый туннель подтверждает себя своим `TestHost`/`TestPort`: канал к заказчику
  может не подняться при живом канале к RevitServer;
- соединение, поднятое **вручную до** запуска пайплайна, по завершении
  не разрывается;
- если обязательный туннель не поднялся, поднятые до него разрываются, шаги
  не выполняются и пайплайн возвращает код 1 (иначе прогон отработал бы вхолостую).

Настройки старого образца, где блок `Vpn` описывал одно подключение,
читаются по-прежнему: такой конфиг разбирается как список из одного туннеля.

Проверить один канал, не трогая настройки:

```bash
powershell -ExecutionPolicy Bypass -File 00_Start_RunScript.ps1 -VpnOnly "RevitServer"
```

Посмотреть имена подключений SoftEther:

```bash
"C:\Program Files\SoftEther VPN Client\vpncmd.exe" /client localhost /cmd AccountList
```

### WireGuard

Туннель WireGuard — это служба Windows `WireGuardTunnel$<имя>`. Пайплайн её
включает и выключает, но **не создаёт**: службу заводит человек один раз,
от имени администратора:

```bash
"C:\Program Files\WireGuard\wireguard.exe" /installtunnelservice "C:\путь\customer-wg.conf"
```

Имя туннеля в настройках — это имя файла `.conf` без расширения. Если службы
нет, пайплайн пишет в лог эту же команду с подставленным именем. Паролей
у WireGuard нет: ключи лежат в `.conf`, который клиент шифрует средствами
Windows.

### OpenVPN

Пайплайн запускает свой процесс `openvpn.exe` и управляет им через интерфейс
управления на `127.0.0.1:<ManagementPort>`: по нему же спрашивается состояние
и отдаётся команда корректного завершения. Журнал самого клиента пишется рядом
с логом пайплайна, файлом `openvpn-<название туннеля>.log`.

- Профиль ищется по имени в `%USERPROFILE%\OpenVPN\config` и
  `C:\Program Files\OpenVPN\config`, в том числе во вложенных папках.
  Если профиль лежит в другом месте, указывается `ProfilePath`.
- Для запуска по расписанию годится только профиль с авторизацией
  по сертификату. Профиль с директивой `auth-user-pass` без файла спрашивает
  логин и пароль в диалоге — отвечать на него некому, поэтому такой профиль
  отклоняется на старте с сообщением в логе.
- Туннель, поднятый вручную через клиент OpenVPN GUI, распознаётся по
  запущенному процессу с этим профилем: вторым процессом он не поднимается
  и по завершении работы не разрывается.
- У каждого туннеля OpenVPN должен быть свой `ManagementPort`.

### Запуск из Планировщика заданий

- Служба **SoftEther VPN Client (`SEVPNCLIENT`)** должна быть запущена и в режиме
  автозапуска — пайплайн не стартует её сам, а пишет об этом ошибку в лог.
  Настройки подключений хранятся в самой службе, поэтому работают и без входа
  пользователя в систему.
- В задаче выбрать «Выполнять вне зависимости от регистрации пользователя».
- Если в списке есть туннель **WireGuard** или **OpenVPN**, в задаче нужен
  режим «Выполнить с наивысшими правами»: без прав администратора служба
  туннеля не запустится, а `openvpn.exe` не создаст маршруты. Пайплайн
  проверяет это на старте и пишет в лог понятную ошибку.
- Задача считается неуспешной по коду возврата `1` — на него можно повесить
  повторный запуск или уведомление.
- Учётной записи задачи нужен доступ к сетевым папкам из `config.json`.

## Внешние зависимости

- Autodesk Revit 2021 → `RevitServerTool.exe`

## Сборка поставки для контрагентов

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "build.ps1"
```

Скрипт `build.ps1` собирает папку `dist/` для передачи наружу:

- удаляет комментарии из `.ps1` и `Settings.html`, добавляет лицензионный заголовок;
- вместо боевого `config.json` кладёт **обезличенный шаблон** `src/config.template.json`
  (пустые адреса серверов, пути и фильтры; стандартные пути к утилитам и набор
  шагов сохранены как значения по умолчанию);
- пересобирает `Инструкция.pdf` из `docs/Инструкция.md`.

Требуется Microsoft Edge или Google Chrome (для PDF). Исходники в `src/` не меняются —
правим их, а `dist/` только пересобираем. Боевой `config.json` с реальными адресами
остаётся в `src/` и в поставку **не попадает**.

> Если в `config.json` добавили новый ключ, добавьте его и в `config.template.json` —
> при сборке `build.ps1` сверяет ключи и предупредит, если шаблон отстал.
