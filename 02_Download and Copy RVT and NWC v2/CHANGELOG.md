# CHANGELOG — Download and Copy RVT and NWC (v2)

## 2.5 — 19.08.2026

- Добавлены клиенты **WireGuard** и **OpenVPN**: выбираются в строке туннеля
  наравне с SoftEther и встроенным VPN Windows.
- WireGuard: туннель включается и выключается как служба Windows
  `WireGuardTunnel$<имя>`. Службу пайплайн не создаёт — при её отсутствии
  в лог пишется готовая команда установки.
- OpenVPN: пайплайн поднимает свой процесс `openvpn.exe` с интерфейсом
  управления, по нему же спрашивает состояние и корректно завершает клиент.
  Профиль ищется по имени в папках OpenVPN пользователя и программы либо
  задаётся путём к `.ovpn`. Журнал клиента пишется рядом с логом пайплайна.
- Профиль OpenVPN, спрашивающий логин и пароль в диалоге, отклоняется
  на старте с объяснением: по расписанию отвечать на запрос некому.
- Туннель, поднятый вручную через клиент OpenVPN GUI, распознаётся
  и не поднимается вторым процессом.
- WireGuard и OpenVPN требуют прав администратора. Если их нет, в лог уходит
  понятная ошибка вместо отказа службы по таймауту.
- У каждого туннеля OpenVPN свой порт управления; редактор настроек
  предупреждает, если порт повторяется.
- Повторная попытка подключения: клиент VPN может отчитаться об успехе,
  а канал не заработать. Перед следующей попыткой подключение разрывается.
  Число попыток задаётся ключом `ConnectAttempts`, по умолчанию 2.
- Туннель, который не заработал за отведённое время, теперь разрывается,
  а не остаётся поднятым.
- В логе видно, на каком именно этапе отказ: клиент не подключился или
  подключился, но узел за туннелем не ответил.
- Исправлен разбор настроек старого образца: ключ `Enabled` блока `Vpn`
  больше не принимается за выключатель самого туннеля.

## 2.4 — 19.08.2026

- VPN настраивается списком туннелей: у каждого свой клиент, своё имя
  подключения, свой узел для проверки и свой выключатель. Ключ `Connections`
  в блоке `Vpn`.
- Туннель можно пометить необязательным (`Required: false`) — пайплайн
  продолжит работу, если этот канал не поднялся.
- Туннели поднимаются по порядку и разрываются в обратном. Если обязательный
  туннель не поднялся, поднятые до него разрываются.
- Ключ `-VpnOnly` у `00_Start_RunScript.ps1` поднимает только названные
  туннели — для проверки одного канала без правки `config.json`.
- `Settings.html`: раздел VPN стал списком туннелей с переключателем у каждого,
  выбором клиента, порядком подключения и проверкой полей по каждому туннелю.
- Настройки старого образца с одним подключением читаются без изменений.

## 2.1 — 12.08.2026

- Подключение VPN перед запуском: SoftEther (`vpncmd.exe`) или встроенный
  VPN Windows (`rasdial.exe`). Блок `Vpn` в `config.json`, по умолчанию
  выключен.
- Соединение, поднятое вручную до запуска, не разрывается. Если VPN
  не поднялся — шаги не выполняются, пайплайн возвращает код 1.
- Факт подключения проверяется доступностью узла (`TestHost`/`TestPort`),
  а не только статусом клиента.
- Пароли в конфигурации не хранятся; при необходимости указывается имя
  переменной окружения.
- Сохранение настроек больше не удаляет незнакомые странице ключи конфига.

## 2.0 — 12.08.2026

Исправлены критичные проблемы первой версии:

- Все скрипты переведены в UTF-8 с BOM — корректное чтение и Windows
  PowerShell 5.1, и PowerShell 7.
- Устранено зависание на выводе внешних утилит больше 4 КБ; добавлены
  таймауты с завершением дерева процессов.
- Шаги возвращают статус оркестратору; пайплайн возвращает Планировщику
  код 0/1 (раньше итог всегда был «завершено»).
- Пустой фильтр больше не превращается в «копировать всё» или
  «не выгружать ничего».
- Папка логов создаётся рядом со скриптом независимо от рабочего каталога.
- Служебные NWD удаляются адресно, а не по маске `*.nwd`.
- Успех внешних процессов определяется по коду возврата, а не по поиску
  слова «ERROR» в выводе.
- Общая логика вынесена в `common.ps1`.
